# Тест-кейсы

Тест-кейсы составлены по [чек-листу](checklist.md) и покрывают все функциональные требования с приоритетом M. Исходные данные — демо-набор [`db/seed/demo.sql`](../../db/seed/demo.sql), пароль всех демо-пользователей `Demo_Pass1`. Адреса API даны по проекту и сверяются с OpenAPI при выполнении.

Приоритет тест-кейса: **Высокий** — блокирует основной сценарий, **Средний** — важная функция с обходным путём, **Низкий** — второстепенная проверка.

Результаты выполнения фиксируются в протоколах `test-run-<дата>.md`.

## Auth

### TC-01. Регистрация с корректными данными
| Атрибут | Значение |
|---|---|
| Приоритет | Высокий |
| Требования | FR-AUTH-01, UC-01 |
| Модуль | Auth / Регистрация |
| Исходные данные | Пользователя `new_user` нет в системе |

**Шаги**
1. Отправить `POST /api/auth/register` с телом `{"username":"new_user","email":"new_user@example.com","password":"Strong_Pass1"}`.
2. Выполнить вход с этими данными (`POST /api/auth/login`).

**Ожидаемый результат**
1. Ответ `201 Created`, в теле — `id` и `username` нового пользователя, пароля и хеша в ответе нет.
2. Вход успешен (`200 OK`), роль пользователя — `User`.

### TC-04. Пароль хранится только в виде хеша
| Атрибут | Значение |
|---|---|

### TC-05. Вход выдаёт Access и Refresh токены
| Атрибут | Значение |
|---|---|
| Приоритет | Высокий |
| Требования | FR-AUTH-03, FR-AUTH-04, UC-02 |
| Модуль | Auth / Вход |
| Исходные данные | Пользователь `user_1`, пароль `Demo_Pass1` |

**Шаги**
1. Отправить `POST /api/auth/login`.
2. Декодировать `accessToken` (jwt.io или Postman).
3. Проверить заголовок `Set-Cookie` ответа.

**Ожидаемый результат**
1. `200 OK`, в теле `accessToken`.
2. Claims `sub`, `unique_name`, `role` = `User`, `jti`, `iat`, `exp`; `exp − iat` = 900 с.
3. Cookie `rt` с атрибутами `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/api/auth`, сроком 7 дней. В `REFRESH_TOKENS` появилась строка с хешем, а не с самим токеном.

### TC-07. Ротация Refresh-токена
| Атрибут | Значение |
|---|---|
| Приоритет | Высокий |
| Требования | FR-AUTH-05, UC-03 |
| Модуль | Auth / Токены |
| Исходные данные | Выполнен вход `user_1`, сохранена cookie `rt` (R1) |

**Шаги**
1. Отправить `POST /api/auth/refresh` с cookie R1.
2. Повторно отправить `POST /api/auth/refresh` со старой cookie R1.

**Ожидаемый результат**
1. `200 OK`, новый `accessToken` и новая cookie R2. В БД у R1 заполнены `REVOKED_AT` и `REPLACED_BY_TOKEN_ID` (ссылка на R2).
2. `401 Unauthorized`. Поскольку предъявлен отозванный токен, все токены пользователя отозваны (FR-AUTH-06), в журнале — событие безопасности.

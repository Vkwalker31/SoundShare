# Проверки безопасности (задание 4)

Проверки выполнены коллекцией Postman (папка `08 Security` и негативные запросы других папок), интеграционными тестами (`SecurityScenarioTests`, `DatabaseConstraintTests`) и вручную. Доказательства — [newman-report.html](evidence/newman-report.html), [db-checks.txt](evidence/db-checks.txt), [TC-38-db-down.txt](evidence/TC-38-db-down.txt).

## 1. Доступ без авторизации по прямому URL

| Проверка | Ожидание | Результат |
|---|---|---|
| `GET /api/rooms`, `/api/users/me`, `/api/admin/users`, `/api/admin/audit-logs`, `/api/tracks` без токена | 401 | 401 — Пройдено |
| Подделанный или просроченный JWT | 401 | 401 — Пройдено |
| Токен в query-параметре для REST (`?access_token=`) | 401 (только для `/hubs/*`) | 401 — Пройдено |
| Подключение к `/hubs/room` без токена | 401 | 401 — Пройдено |
| Клиент: открыть `/`, `/rooms/1`, `/admin/users` без входа | Перенаправление на `/login` | Перенаправление — Пройдено (UI-тест `Anonymous_OpensRooms_RedirectedToLogin`) |
| Обычный пользователь открывает `/api/admin/*` | 403 | 403 — Пройдено |
| Contributor закрепляет трек, пропускает трек, банит модератора | 403 | 403 — Пройдено |

## 3. Ошибки не раскрывают внутренние детали

| Проверка | Ожидание | Результат |
|---|---|---|
| Ошибки валидации, 401/403/404/409 | ProblemDetails без стека, путей, SQL, имён таблиц | Пройдено (проверка в каждом негативном запросе коллекции) |
| Некорректный JSON | 400 без деталей реализации | 400, сообщение парсера JSON без стека — Пройдено |
| БД недоступна | 503 с `traceId` | Сначала 500 (DEF-022), после исправления — 503 — Пройдено |
| Неверное имя пользователя и неверный пароль | Одинаковое сообщение | «Invalid username or password.» в обоих случаях — Пройдено |
| Заголовки ответа | Нет версии фреймворка (`X-Powered-By`) | Только `Server: Kestrel` — замечание низкой важности, скрывается обратным прокси |

## 5. Прочее

| Проверка | Результат |
|---|---|
| Ограничение частоты входа | 6-я попытка за минуту с одного IP → 429 с `Retry-After` (проверено вручную при приёмке backend; в автотестах и коллекции лимит поднят, чтобы не мешать прогону) |
| Refresh-токен | Только в cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/auth`, в БД — SHA-256; повторное использование отзывает все сессии |
| Пароли | PBKDF2-SHA512, 100 000 итераций (Identity v3) |
| SQL-инъекции | Инспекция кода: все запросы параметризованы (EF Core, `OracleParameter`, переменные привязки), конкатенации SQL с вводом пользователя нет |
| Секреты | Пароли БД и ключ JWT только из переменных окружения; `.env` в `.gitignore`; приложение запускается только при ключе ≥ 32 символов |
| Уязвимые зависимости | Закрыто DEF-021: обновление ASP.NET Core до 10.0.13, транзитивное закрепление `System.Security.Cryptography.Pkcs` 10.0.13 |

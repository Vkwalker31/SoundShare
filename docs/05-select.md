# Этап 5. SELECT-запросы

Скрипт: [`db/queries/05_select.sql`](../db/queries/05_select.sql). Только чтение, выполняется на демо-данных.

| № | Запрос | Приёмы | Где используется |
|---|---|---|---|
| 5.1 | Очередь комнаты в порядке воспроизведения | CTE, `ROW_NUMBER() OVER`, `LISTAGG`, `LEFT JOIN`, `NULLS LAST` | `GET /api/rooms/{id}/queue` |
| 5.2 | Текущий трек: прошло и осталось секунд | Арифметика `INTERVAL DAY TO SECOND`, `EXTRACT`, `GREATEST` | Синхронизация плеера, `PlaybackWorker` |
| 5.3 | Публичные комнаты с числом участников и текущим треком | `GROUP BY`, скалярный подзапрос | `GET /api/rooms` |
| 5.4 | Участники комнаты: роль, статус, срок бана | `CASE`, пользовательская сортировка ролей | Панель участников |
| 5.5 | Рейтинг треков по всем комнатам | Агрегат + `RANK`/`DENSE_RANK` (разница видна на равных суммах) | Статистика |
| 5.6 | Самые активные участники каждой комнаты | Оконная функция с `PARTITION BY`, агрегаты в окне | Статистика комнаты |
| 5.7 | Исполнители: треки и число воспроизведений | `COUNT(DISTINCT)`, `LISTAGG(DISTINCT …)` (19c+) | Каталог |
| 5.8 | Пользователи для администратора, вторая страница | `OFFSET … FETCH NEXT`, коррелированный подзапрос | `GET /api/admin/users` |
| 5.9 | Поиск по названию или исполнителю без учёта регистра | `UPPER … LIKE`, `EXISTS` | `GET /api/tracks?query=` |
| 5.10 | Прогресс голосования за пропуск | `CROSS JOIN` с агрегатом, `FLOOR(n / 2) + 1` | Кнопка «Пропустить» |
| 5.11 | Треки, которые ещё не ставили в очередь | Анти-соединение `NOT EXISTS` | Рекомендации |
| 5.12 | Кто чаще голосует против | Условная агрегация `SUM(CASE …)`, `HAVING` | Модерация |
| 5.13 | История воспроизведения с паузами | `LAG() OVER`, разность дат в минутах | История комнаты |
| 5.14 | Личный плейлист с накопительной длительностью | `SUM() OVER (ORDER BY …)` и `SUM() OVER ()` | Плейлист |
| 5.15 | Позиции очереди по статусам и комнатам | `PIVOT` | Отчёт |
| 5.16 | Итоги по комнатам и общий итог | `GROUP BY ROLLUP`, `GROUPING()` | Отчёт |

## Замечания

- Рейтинг трека не хранится, а вычисляется как `SUM(vote_value)`: так голоса и счётчик не могут разойтись (3НФ). На этапе 7 для больших объёмов сравниваются планы с индексами по `TRACK_VOTES` и `PLAYLIST_TRACKS`.
- Поиск без учёта регистра использует `UPPER(...)`; для уникальности имён пользователей построены функциональные индексы `UPPER(username)`, `UPPER(email)`.
- Все запросы параметризованы переменными привязки.

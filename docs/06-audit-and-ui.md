# Этап 6. Журналирование и интерфейсы

## 1. Как устроен журнал

| Источник | Кто пишет | Что попадает |
|---|---|---|
| `HTTP` | `AuditMiddleware` приложения | Каждый изменяющий запрос: пользователь, действие (`Queue.Vote`, при неуспехе — `Queue.VoteFailed`), метод, путь, код ответа, IP, `CorrelationId`, длительность |
| `HUB` | `RoomHub` (SignalR) | Действия через WebSocket |
| `DOMAIN` | Триггеры БД ([`V007__audit_triggers.sql`](../db/migrations/V007__audit_triggers.sql)) | Смена роли, блокировка и разблокировка пользователя, бан в комнате — кем бы ни было сделано изменение, даже вручную в SQL*Plus |
| `SYSTEM` | Фоновые службы | Проверки и обслуживание |

Свойства журнала:
- **только добавление** — у `SOUNDSHARE_APP` на `AUDIT_LOGS` есть лишь `SELECT, INSERT` (запрос 6.12); попытка изменить или удалить запись даёт `ORA-01031` (на 23ai — `ORA-41900`), это проверяет интеграционный тест `AppUser_ForbiddenStatement_IsDenied`;
- **не замедляет запрос** — middleware кладёт запись в ограниченный `Channel`, в БД её пачками пишет `AuditWriterService`;
- **детали в JSON** — `CHECK (details IS JSON STRICT)`, извлечение через `JSON_VALUE` (запрос 6.8);
- **не обходится** — триггеры фиксируют изменения прав, даже если они сделаны мимо API.

## 2. Запросы журналирования

Скрипт: [`db/queries/06_audit.sql`](../db/queries/06_audit.sql).

| № | Запрос | Приёмы |
|---|---|---|
| 6.1 | Лента событий с постраничной навигацией по ключу | Keyset-пагинация `id < :cursor` (стабильна при вставках, в отличие от `OFFSET`) — так работает `GET /api/admin/audit-logs?cursor=` |
| 6.2 | Действия пользователя за период | Фильтр по пользователю и времени |
| 6.3 | Неуспешные запросы по действию и коду | `GROUP BY`, `status_code >= 400` |
| 6.4 | Подозрение на подбор пароля | `HAVING COUNT(*)` по IP за час |
| 6.5 | Активность пользователей с подытогами | `ROLLUP`, `GROUPING()` |
| 6.6 | Производительность эндпоинтов | `PERCENTILE_CONT(0.5 / 0.95)` — p50 и p95 для NFR-PERF |
| 6.7 | Трассировка запроса по `CorrelationId` | `KEEP (DENSE_RANK LAST …)` |
| 6.8 | Параметры созданных комнат из JSON | `JSON_VALUE` |
| 6.9 | Гистограмма активности по часам | `TRUNC(…, 'HH24')`, `RPAD` |
| 6.10 | Демонстрация триггеров | Изменения → записи `DOMAIN` (откатываются) |
| 6.11 | Действия администраторов и изменения прав | `LIKE 'Admin.%'` или `source = 'DOMAIN'` |
| 6.12 | Права на журнал | `USER_TAB_PRIVS` |
| 6.13 | Кандидаты на архивирование | Записи старше 180 дней |

Клиент — Blazor WebAssembly. Макеты экранов, которые используют запросы этапов 5–6:

### Вход
```
+--------------------------------------------------+
|  SoundShare                                       |
|        +-----------------------------+           |
|        | Имя пользователя [________] |           |
|        | Пароль           [________] |           |
|        |      [ Войти ]  Регистрация |           |

+--------------------------------------------------+
```

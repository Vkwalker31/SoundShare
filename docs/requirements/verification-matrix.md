# Матрица верификации требований

Для каждого требования [технического задания](../01-technical-specification.md) указан способ проверки. Требования, для которых способ сформулировать было нельзя, переписаны (раздел 2); найденные при верификации несоответствия зарегистрированы в [ISSUES.md](../../ISSUES.md).

## 1. Способы проверки

| Код | Способ | Что считается подтверждением |
|---|---|---|
| **ТК** | Ручной тест-кейс | Тест-кейс из [test-cases.md](../testing/test-cases.md) выполнен со статусом «Пройден» |
| **АТ** | Автотест | Юнит-, интеграционный или сценарный тест проходит в CI; для схемы БД — [constraints_test.sql](../../db/tests/constraints_test.sql) |
| **И** | Инспекция | Просмотр кода, конфигурации или схемы по чек-листу ревью |
| **Д** | Демонстрация | Показ функции на демо-сценарии без измерений |
| **Ан** | Анализ / измерение | Расчёт или замер (нагрузочный тест, `EXPLAIN PLAN`, анализ журнала) с числовым критерием |

## 2. Переписанные требования

| ID | Было | Почему непроверяемо | Стало |
|---|---|---|---|
| FR-AUD-04 | «Запись не задерживает ответ» | Нет порога: любая задержка — «задержка» | Постановка записи в очередь ≤ 1 мс (p99), без обращения к БД; при заполненной очереди запись уходит в резервный лог, растёт `audit_dropped_total` |
| NFR-PERF-03 | «Нет N+1: проекции в DTO, AsNoTracking» | Описывает способ реализации, а не измеримое свойство | Один REST-запрос выполняет не более 5 SQL-команд независимо от числа элементов в ответе |
| NFR-REL-03 | «Клиент переподключается автоматически и восстанавливает состояние» | Нет сроков и критерия «восстановлено» | Переподключение ≤ 30 с; в течение 1 с после него показывается текущая версия очереди |
| NFR-SCALE-01 | «Масштабирование за балансировщиком» | Нет условия успеха, стенд с балансировщиком вне области | Перезапуск экземпляра API не разлогинивает пользователей и не теряет данные очереди (состояние не хранится в памяти процесса) |

# Этап 4. DML-запросы

Скрипт: [`db/queries/04_dml.sql`](../db/queries/04_dml.sql). Выполняется под `SOUNDSHARE` на демо-данных и в конце откатывает транзакцию, поэтому его можно запускать сколько угодно раз:

```bash
docker cp db/queries soundshare-oracle:/tmp/queries
docker exec -it -e NLS_LANG=AMERICAN_AMERICA.AL32UTF8 soundshare-oracle sqlplus soundshare@//localhost:1521/FREEPDB1 @/tmp/queries/04_dml.sql
```

Параметры передаются через переменные привязки SQL*Plus (`VARIABLE`, `:room_id`) — так же, как приложение передаёт их через `OracleParameter`: значения не склеиваются с текстом запроса, план выполнения переиспользуется, SQL-инъекция невозможна.

| № | Операция | Тип | Требование | Что показывает |
|---|---|---|---|---|
| 4.1 | Регистрация | `INSERT … RETURNING` | FR-AUTH-01 | Идентификатор из `IDENTITY`; роль и активность берутся из `DEFAULT ON NULL` |
| 4.2 | Выдача refresh-токена | `INSERT` | FR-AUTH-03 | В БД хранится только `STANDARD_HASH(…, 'SHA256')` — `RAW(32)`, сам токен не сохраняется |
| 4.3 | Ротация токена | `INSERT` + `UPDATE` | FR-AUTH-04 | Старый токен отзывается и ссылается на новый (`REPLACED_BY_TOKEN_ID`) — по этой цепочке обнаруживается повторное использование |
| 4.4 | Создание комнаты | 3 × `INSERT` в одном блоке | FR-ROOM-01 | Комната, её очередь и участник-владелец создаются атомарно |
| 4.5 | Вход в комнату | `UPDATE` + `MERGE` | BR-ROOM-01, BR-ROOM-03 | Сначала выход из текущей комнаты (пользователь в одной комнате — уникальный функциональный индекс), затем вставка или повторный вход; забаненный не войдёт — условие в `WHEN MATCHED … WHERE` |
| 4.6 | Добавление трека | `INSERT … SELECT … WHERE` | BR-VOTE-01 | Лимит 3 активных трека проверяется тем же оператором; автор сразу голосует +1 |
| 4.7 | Запуск воспроизведения | `UPDATE … WHERE id = (… FETCH FIRST 1 ROW ONLY)` | FR-RT-04 | Выбор следующего трека: закреплённые → рейтинг → время добавления; не больше одного `PLAYING` на очередь |
| 4.8 | Голосование | `MERGE` с удалением строки | BR-VOTE-02, BR-VOTE-03 | Один оператор ставит, меняет и снимает голос. При снятии ветка `UPDATE` сохраняет старое значение — иначе `CHECK (vote_value IN (-1, 1))` сработал бы раньше удаления (дефект DEF-007) |
| 4.9 | Автоудаление | `UPDATE` с коррелированным подзапросом | BR-VOTE-05 | Трек с суммой голосов ≤ −5 и без закрепления получает `AUTO_REMOVED` |
| 4.10 | Закрепление | `UPDATE … AND EXISTS` | BR-VOTE-08 | Право проверяется в самом запросе: у участника 0 строк, у владельца 1 |
| 4.11 | Пропуск большинством | `INSERT` + 2 × `UPDATE` | BR-VOTE-06 | `PLAYING → SKIPPED`, если голосов × 2 больше числа участников онлайн, затем запускается следующий трек |
| 4.12 | Бан | `UPDATE` | BR-ROOM-05 | Выход из комнаты и срок бана; `CHECK` требует, чтобы бан заканчивался после выхода |
| 4.13 | Передача владения | 2 × `UPDATE` | BR-ROOM-04 | Многостолбцовое сравнение `(room_id, user_id) = (подзапрос)`: модератор, иначе самый давний участник |
| 4.14 | Блокировка пользователя | 2 × `UPDATE` | FR-USR-03 | Блокировка и отзыв всех сессий |
| 4.15 | Смена роли | `UPDATE … AND (SELECT COUNT(*)) > 1` | FR-USR-02 | Последнего администратора нельзя понизить: 0 строк; после назначения второго — 1 строка |
| 4.16 | Удаление аккаунта | 2 × `UPDATE` | FR-USR-05, BR-ACC-01 | Анонимизация вместо физического удаления: история голосов и журнал сохраняют ссылочную целостность |
| 4.17 | Закрытие пустых комнат | 2 × `UPDATE` с `NOT EXISTS` | BR-ROOM-06 | Комната без участников помечается `EMPTY_SINCE` и закрывается через 10 минут |
| 4.18 | Удаление трека из плейлиста | удаление + `UPDATE` | FR-PL-02 | Позиции сдвигаются, уникальный индекс `(playlist_id, position)` не нарушается |
| 4.19 | Удаление плейлиста | удаление | FR-PL-02 | Позиции удаляются каскадно (`ON DELETE CASCADE`), «сирот» нет |
| 4.20 | Очистка токенов | удаление | NFR-SEC-04 | Просроченные и отозванные более 30 дней назад |
| 4.21 | Запись аудита | `INSERT` с `JSON_OBJECT` | FR-AUD-01 | Детали проходят `CHECK (details IS JSON STRICT)` |

## Особенности Oracle

- `RETURNING … INTO` возвращает сгенерированный ключ без повторного `SELECT`.
- `MERGE` с веткой удаления выполняет вставку, изменение и удаление за один проход и одну блокировку строки.
- `FETCH FIRST n ROWS ONLY` в подзапросе (с 12c) заменяет конструкции с `ROWNUM`.
- Все даты хранятся в UTC: `SYS_EXTRACT_UTC(SYSTIMESTAMP)`; интервалы — `INTERVAL '7' DAY`.
- Приложение (`SOUNDSHARE_APP`) не имеет права удалять строки из `USERS`, `ROOMS`, `ROOM_MEMBERS`, `AUDIT_LOGS` — поэтому удаление аккаунта и выход из комнаты реализованы через `UPDATE`.

## Результат прогона

Все 21 операция выполняются без ошибок на свежих демо-данных; ожидаемые 0 строк — в 4.10 (участник не может закрепить) и в 4.15 (нельзя понизить последнего администратора).
